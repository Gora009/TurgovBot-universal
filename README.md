# TurgovBot (universal)

Telegram-бот и API юридического помощника для ролевых GTA 5 серверов. Бот знает
законы каждого сервера, отвечает на вопросы со ссылками на статьи, помогает
составлять жалобы, иски и уголовные дела, разбирает чужие жалобы и обслуживает
десктоп-оверлей и сайт.

Это универсальная версия. Она работает с любым OpenAI-совместимым API по обычному
API-ключу: DeepSeek, OpenAI, OpenRouter, Qwen, Groq, локальные Ollama и vLLM.
Google Cloud для работы не нужен.

## Поддерживаемые проекты

| Проект | Форум | Серверов с законами |
|---|---|---|
| Majestic RP | forum.majestic-rp.ru | 19 |
| GTA 5 RP | forum.gta5rp.com | 8 |
| RMRP | forum.rmrp.ru | 1 (общая база на все серверы) |
| Россия Онлайн | forum.russia.online | 3 |
| NOVA RP | forum.nova-rp.com | 2 |

Законы собираются с форумов автоматически и обновляются по расписанию. Список
проектов, серверов и разделов форума находится в `knowledge/sources.py`.

## Что умеет бот

- Отвечает на вопросы по законам выбранного сервера. Сначала быстрая модель выбирает
  нужные кодексы, затем основная модель отвечает по их полному тексту и ссылается
  на статьи. К ответу подмешиваются судебные прецеденты сервера.
- Ролевой помощник для адвоката и прокурора: ведёт дело, хранит историю и сжатую
  «карту дела», чтобы длинные дела не теряли контекст.
- Составляет жалобы, исковые заявления и уголовные дела. Уголовное дело
  выгружается в файл `.docx`.
- Разбирает жалобы в прокуратуру по этапам и анализирует чужие жалобы по ссылке
  на тему форума.
- Ищет пробелы и противоречия в законах (фоновая очередь с кэшем результатов).
- Принимает голосовые вопросы в Telegram и голос в оверлее.
- Отдаёт API для оверлея и сайта: поиск статей, советы, вход через Telegram,
  лицензии, ключи API.
- Админ-панель в Telegram: пользователи, баны, лимиты, рассылки, репорты, заявки,
  промо-акции, обновление законов, просмотр настроек моделей.

## Чем эта версия отличается от исходной

| Было (Gemini и Google Cloud) | Стало |
|---|---|
| Модели Gemini через Vertex AI и сервис-аккаунт | Любой OpenAI-совместимый API по ключу |
| Законы в Google Cloud Storage | Локальное хранилище `data/storage` |
| Распознавание речи Google Speech-to-Text | Whisper-совместимый API (`/audio/transcriptions`) |
| Уголовные дела в Google Docs | Файлы `.docx`, ссылка на скачивание через API |
| Журнал действий админов в Google Sheets | Таблица `admin_action_log` в базе |

Функции, сценарии диалогов и системные промпты не изменились. Все обращения к
модели проходят через адаптер `common/llm/compat.py`: он повторяет интерфейс
Gemini SDK, которым пользуется код бота, и переводит запросы в формат
`/chat/completions`.

## Модели и роли

Модели разделены по ролям. У каждой роли может быть свой поставщик и свой ключ.

| Роль | Для чего | Если не задана |
|---|---|---|
| `SMART` | Ответы, помощник, документы, анализ жалоб | обязательна |
| `FAST` | Выбор законов и прецедентов, улучшение вопроса, сводки | используется `SMART` |
| `VISION` | Картинки: распознавание паспорта, скриншоты из дел | используется `SMART` |
| `EMBED` | Векторный поиск по законам | поиск идёт по каталогу статей (полнотекстовый) |
| `STT` | Распознавание голоса | голосовые функции выключены |

Минимальная настройка в `.env`:

```env
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-...
LLM_SMART_MODEL=deepseek-chat
```

Для роли задаются переменные `LLM_<РОЛЬ>_BASE_URL`, `LLM_<РОЛЬ>_API_KEY` и
`LLM_<РОЛЬ>_MODEL`. Если адрес или ключ не указаны, берутся общие `LLM_BASE_URL` и
`LLM_API_KEY`. Примеры для DeepSeek, OpenAI, OpenRouter, Groq и Ollama, а также
ограничения разных поставщиков описаны в [docs/LLM_PROVIDERS.md](docs/LLM_PROVIDERS.md).

DeepSeek (deepseek-chat) читает текст с картинок: проверено 25.11.2026 на распознавании
текста со скриншота. Векторы и распознавание речи он не делает. Без `EMBED` бот ищет
статьи по каталогу (полнотекстовый поиск), без `STT` голосовые функции выключены.

## Установка

Понадобятся сервер с Docker и Docker Compose, токен бота от
[@BotFather](https://t.me/BotFather) и API-ключ поставщика моделей.

1. Скачайте код и создайте файл настроек:

   ```bash
   git clone https://github.com/Gora009/TurgovBot-universal.git
   cd TurgovBot-universal
   cp .env.example .env
   ```

2. Заполните в `.env`:
   - `TELEGRAM_BOT_TOKEN` и `SUPER_ADMIN_ID` (ваш Telegram ID);
   - пароль базы данных `DB_PASS`;
   - `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_SMART_MODEL` и при необходимости другие роли;
   - `DEVICE_JWT_SECRET`: длинная случайная строка, например результат
     `openssl rand -hex 32`. Без неё вход устройств и сайта не переживает перезапуск;
   - `PUBLIC_BASE_URL`: внешний адрес API. Нужен для ссылок на скачивание документов;
   - доступ к форумам, если законы закрыты авторизацией (Majestic RP, Россия Онлайн,
     GTA 5 RP): логин и пароль `FORUM_*_LOGIN` и `FORUM_*_PASSWORD` либо cookie
     `xf_user` своего аккаунта в `FORUM_*_XF_USER`. Cookie берётся из браузера
     после входа на форум (инструменты разработчика, вкладка с cookie).

3. Создайте таблицы в базе и запустите сервисы:

   ```bash
   docker compose up -d db
   docker compose run --rm migrate
   docker compose up -d --build
   ```

   Команду `docker compose run --rm migrate` нужно повторять после каждого
   обновления кода, в котором появились новые миграции.

4. Откройте бота в Telegram от имени `SUPER_ADMIN_ID`, отправьте `/admin` и проверьте раздел «Модели и ключи»:
   там видно, какая модель стоит на каждой роли.

Подробная инструкция с переносом существующей базы, бэкапами и автодеплоем:
[STARTUP_GUIDE.md](STARTUP_GUIDE.md).

## Перенос со старой версии на Gemini

- База данных подходит. Примените миграции (`docker compose run --rm migrate`):
  - 027: таблица журнала действий админов;
  - 028 и 029: колонки и таблицы, которые код использовал, но миграции не создавали.
    На старой базе они уже есть, миграции ничего не меняют;
  - 030: удаляет закрытые серверы GTA5RP (19 штук) и NOVA RP Mirage вместе с их
    законами и прецедентами. Список в файле миграции. Перед применением на рабочей
    базе сделайте бэкап;
  - 031: время последнего сообщения темы для пропуска неизменённых законов.
- Законы и прецеденты бот берёт из базы, если файла нет в локальном хранилище,
  поэтому повторно загружать их не обязательно.
- Векторы, посчитанные Gemini, несовместимы с векторами другой модели. После
  настройки роли `EMBED` законы нужно переиндексировать повторным синком.
- Каталог статей (поиск оверлея и сайта, подборка статей для помощника) бот строит сам
  при первой синхронизации законов. Вручную, например после правки разбора:
  `python scripts/build_law_catalog.py --all --no-enrich`.
- Промпты писались под Gemini. Перед переходом стоит сравнить качество ответов на
  эталонном наборе: `scripts/golden_advice.py` и `data/golden_advice_cases.json`.

## Устройство

Сервисы Docker Compose:

| Сервис | Назначение |
|---|---|
| `db` | PostgreSQL 16 с расширением pgvector |
| `migrate` | Миграции Alembic, запускается вручную: `docker compose run --rm migrate` |
| `bot` | Telegram-бот (`main.py`, python-telegram-bot 22) |
| `api` | FastAPI (`api/main.py`): оверлей, поиск законов, сайт, скачивание файлов |
| `law-embedding-worker` | Фоновый расчёт векторов статей локальной моделью FRIDA |
| `parser-worker` | Парсер форумов на Playwright |
| `flaresolverr` | Прохождение проверки Cloudflare на форумах, где она есть |
| `caddy` | HTTPS и обратный прокси перед API |

Структура кода:

```
main.py                 запуск бота
config.py               настройки, состояния диалогов, роли моделей
user_handlers/          сценарии пользователя: вопросы, помощник, жалобы, дела
admin_handlers/         админ-панель, по модулю на раздел
api/                    FastAPI: роутеры, схемы, безопасность
services/               бизнес-логика: ответы, поиск законов, документы, лицензии
knowledge/              законы и прецеденты: сбор с форумов, список проектов
parsers/                разбор тем форума, HTML в BB-код, распознавание картинок
integrations/           документы дел в .docx, журнал действий админов
common/llm/             адаптер моделей и настройки ролей
common/storage.py       локальное хранилище файлов и подписанные ссылки
prompts/                системные промпты
parser_worker/          отдельный сервис-парсер
alembic/                миграции базы
scripts/                обслуживание: каталог законов, бэкапы, проверки
tests/                  тесты pytest
experimental/           незаконченный валидатор синонимов, ботом не используется
```

Поиск статей для оверлея работает без языковой модели: полнотекстовый поиск
PostgreSQL, триграммы, словарь сленга и синонимов и векторы локальной модели
[FRIDA](https://huggingface.co/ai-forever/FRIDA). Подробно о поиске и RAG:
[docs/RAG_AND_SEARCH.md](docs/RAG_AND_SEARCH.md). Векторный поиск включается, когда
модель FRIDA лежит в `./models` на сервере и задано `LAW_CATALOG_EMBED_ENABLED=true`.

## Как добавить новый проект

1. Добавьте проект и его серверы в `knowledge/sources.py`: адрес раздела форума с
   законами для каждого сервера.
2. Добавьте домен форума в списки разрешённых адресов: `api/url_validator.py` и
   `SUPPORTED_FORUMS` в `parsers/court_case.py`.
3. Если законы закрыты авторизацией, добавьте форум в `FORUM_LOGINS` в
   `parser_worker/worker.py` и `parsers/court_case.py` и задайте логин в `.env`.
4. Напишите тест по образцу `tests/test_nova_rp_onboarding.py`.

## Тесты

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt pytest pytest-asyncio
.venv/bin/python -m pytest -q tests
```

Тестам не нужны база данных и доступ к поставщику моделей: внешние вызовы
подменены. Тесты адаптера моделей находятся в `tests/test_llm_compat.py`.

## Известные ограничения

- Версия проверена тестами, но с реальным поставщиком моделей под нагрузкой ещё не
  запускалась.
- Если суммарный объём законов в запросе больше `LLM_MAX_INPUT_CHARS`
  (по умолчанию 300 000 символов), последние документы не отправляются модели.
  Это сделано под окно 128 тысяч токенов. Для моделей с меньшим окном уменьшите значение.
- Распознавание голоса не потоковое: речь режется на фразы по паузам и отправляется
  фразами, поэтому текст появляется после окончания фразы.

## Безопасность

Токены, ключи и пароли хранятся в `.env` на сервере и в репозиторий не попадают.
Об уязвимостях сообщайте по инструкции из [SECURITY.md](SECURITY.md), а не через
публичные issues.
